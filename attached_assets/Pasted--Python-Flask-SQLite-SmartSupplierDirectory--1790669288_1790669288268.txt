قم بإنشاء تطبيق ويب متكامل بلغة Python (Flask) وقاعدة بيانات SQLite باسم SmartSupplierDirectory. الهدف هو بناء "دليل موردين ذكي" يتطور ذاتياً ويحل مشاكل تكرار البيانات واختلاف اللغات (عربي/إنجليزي).

المتطلبات الأساسية (Functional Requirements):

1. هيكل قاعدة البيانات (Database Schema):
   - جدول Suppliers (الموردين): id, name, email, password_hash, is_active (boolean, default=False).
   - جدول MasterCategories (الأصناف الرئيسية): id, name_ar (مثل: لبنة), name_en (مثل: Labneh), is_approved (boolean, default=True).
   - جدول SubTypes (الأنواع الفرعية): id, master_category_id, name_ar (مثل: جاموس), name_en (مثل: Buffalo), is_approved (boolean, default=False).
   - جدول SupplierProducts (منتجات المورد): id, supplier_id, sub_type_id, price (float, nullable), last_updated (timestamp), is_active (boolean, default=True).

2. صلاحيات المورد (Supplier Role):
   - يمكن للمورد تسجيل الدخول.
   - يرى قائمة بـ MasterCategories (الأصناف الرئيسية) التي أضفتها أنت مسبقاً.
   - قاعدة صارمة: لا يمكن للمورد تعديل اسم MasterCategory.
   - عند اختيار المورد لصنف رئيسي (مثلاً "لبنة")، تظهر له قائمة منسدلة ذكية (Autocomplete) بكل الأنواع الفرعية (SubTypes) التي سجلها الموردون السابقون (مثل: جاموس، بقري، كريمة).
   - إذا وجد نوعه، يختاره. إذا لم يجده، يمكنه إضافة نوع جديد (اسم عربي + اسم إنجليزي)، ولكن يظل "قيد المراجعة" (is_approved = False) حتى توافق الإدارة.
   - يمكن للمورد إدخال "سعر" (اختياري) لكل نوع.
   - يمكن للمورد حذف نوع من ملفه (Soft Delete: is_active = False).
   - يمكن للمورد اقتراح "صنف أساسي جديد" إذا لم يجده في القائمة، ويظل قيد المراجعة حتى توافق الإدارة.

3. منطق النشر (Publishing Logic):
   - قاعدة "الملف المكتمل": إذا اختار المورد صنفاً رئيسياً ولم يضف أي "نوع فرعي" (أو كانت كل أنواعه غير معتمدة)، يظل الملف is_active = False.
   - لا يظهر المورد في نتائج البحث لصاحب العمل إلا إذا كان is_active = True (أي لديه نوع واحد على الأقل معتمد).

4. واجهة صاحب العمل (Employer Role):
   - صفحة بحث بالعربية فقط.
   - عند البحث عن "لبنة"، يبحث النظام في (name_ar و name_en) ويظهر كل الموردين الذين يبيعون "لبنة".
   - بجانب كل مورد، تظهر قائمة بالأنواع المتاحة لديه (سواء كتبت بالعربي أو الإنجليزي).
   - يمكن لصاحب العمل الفلترة أكثر باختيار نوع معين (مثلاً "جاموس")، فتظهر له فقط الموردين الذين يبيعون هذا النوع، مع السعر (إن وجد) وتاريخ آخر تحديث.

5. واجهة المسؤول (Admin - أنت):
   - إضافة MasterCategories (الأصناف الرئيسية) مع الترجمة (عربي/إنجليزي).
   - مراجعة الأنواع الفرعية الجديدة (SubTypes) التي اقترحها الموردون: موافقة (is_approved = True) أو رفض (حذف).
   - مراجعة الأصناف الرئيسية الجديدة التي اقترحها الموردون.
   - لوحة تحكم لعرض إحصائيات (عدد الموردين، عدد الأنواع، إلخ).

المتطلبات التقنية:
   - استخدم Flask للـ Backend.
   - استخدم SQLAlchemy للتعامل مع قاعدة البيانات.
   - استخدم Bootstrap أو Tailwind CSS لجعل الواجهة بسيطة ومقبولة.
   - اكتب الكود في ملفات منفصلة (app.py, models.py, routes.py, templates/).
   - تأكد من وجود تعليقات توضيحية في الكود تشرح كل جزء.
   - استخدم تقنية "البحث الضبابي" (Fuzzy Search) في القوائم المنسدلة لمساعدة الموردين على اختيار النوع الصحيح وتجنب الأخطاء الإملائية.
